# Guía de inicio

## Punto de partida

El repositorio se creó sin contenido, descripción ni una tecnología definida. Este arranque mantiene abiertas las decisiones de producto y de implementación.

## Decisiones pendientes

Antes de implementar la primera funcionalidad, completar:

- **Objetivo:** ¿qué problema resuelve el proyecto?
- **Usuario:** ¿quién lo va a utilizar?
- **Primer caso de uso:** ¿qué acción concreta debe poder completar?
- **Interfaz:** web, móvil, escritorio, terminal u otra.
- **Datos:** qué información necesita y dónde se guardará.
- **Tecnología:** elegirla a partir de las necesidades anteriores.
- **Licencia:** decidir las condiciones de distribución y reutilización antes de incorporar código de terceros o aceptar contribuciones.

## Primera entrega

Elegir un único caso de uso pequeño y escribir su criterio de aceptación:

> Dado [un estado inicial], cuando [el usuario realiza una acción], entonces [un resultado observable].

Después:

1. Crear la estructura de código según las convenciones de la tecnología elegida.
2. Añadir las dependencias imprescindibles y sus archivos de bloqueo, cuando proceda.
3. Documentar requisitos y comandos reales de instalación, ejecución y verificación en el README.
4. Implementar el caso de uso y comprobar su criterio de aceptación.
5. Añadir pruebas y automatización cuando exista comportamiento que verificar.

## Criterio de finalización

La primera entrega estará lista cuando otra persona pueda clonar el repositorio, seguir el README y completar el caso de uso descrito.
